Login & sessions

Add auth to VerxeeUI.app() and you get a sign-in screen, optional two-step code, password reset, sign-out, “session expired” handling, idle timeout and per-permission menus — wired to your backend.

Read this first. A browser UI can never be the thing that keeps people out: anyone can edit JavaScript in their own browser. Verxee UI gives you a secure front end for authentication; identity, sessions, rate limiting and every permission check must be done by your server. Hiding a menu item is a convenience, not protection. See Security.

The 10-line setup

VerxeeUI.app({
  brand: { name: 'Acme Admin', icon: 'bolt' },
  auth: {
    urls: { session: '/api/me', login: '/api/login', logout: '/api/logout', forgot: '/api/forgot' },
    idleTimeout: 15                       // minutes
  },
  sidebar: [{ label: 'Orders', icon: 'shopping-cart', href: '#/orders', can: 'orders.view' }],
  page: [{ type: 'heading', title: 'Dashboard' }]
});

Before sign-in nothing of the app is shown. After it, the topbar gets a user menu with Sign out automatically. A complete working example (screen + backend) is in examples/: run node examples/server.mjs and open /examples/auth.html (admin@example.com / correct horse battery).

The server contract (auth.urls)

EndpointRequestResponse
session GETcookies200 + user JSON, or 401
login POST JSON{ identifier, password } (also sent as email/username)200 user JSON · { twoFactor: true } to ask for a code · 4xx + { message } on failure
verify2fa POST{ code }user JSON or 4xx
forgot POST{ identifier }200 always (never reveal whether the account exists). Omit to hide the link.
logout POST200, and the server destroys the session

The user JSON is whatever you like; these keys are understood: name, email, permissions (array of strings, '*' = everything).

Using your own functions instead

Not a JSON API? Pass functions that return Promises — any of session, login, verify2fa, forgot, logout:

auth: {
  session: () => fetch('/me.php').then(r => r.ok ? r.json() : null),
  login:   ({ identifier, password }) => myLogin(identifier, password),   // reject with new Error('message') to show a message
  logout:  () => fetch('/logout.php', { method: 'POST' })
}

Options

Option
idleTimeoutMinutes of inactivity before automatic sign-out (UI side; set the same on the server)
confirmLogouttrue asks “Sign out?” first
title · subtitle · footerTexts on the sign-in card
textsOverride any string (translations): identifier, identifierType ('email' | 'text'), password, submit, forgotLink, invalid, codeTitle, codeSub, sent, locked, expired, signedOut, idle …
onLogin / eventsdocument.addEventListener('verxee:login', e => e.detail.user) and 'verxee:logout'
// Czech UI, username instead of e-mail
auth: { urls: { … }, texts: { title: 'Přihlášení', identifier: 'Uživatel', identifierType: 'text', password: 'Heslo', submit: 'Přihlásit' } }

What happens automatically

  • Session check on load — shows the app or the sign-in screen; the page is only built after a successful sign-in, and removed from the DOM on sign-out.
  • Two-step code screen (autocomplete="one-time-code") when login answers { twoFactor: true }.
  • 401 anywhere — requests made with VerxeeUI.fetch() that come back 401 drop the user to the sign-in screen with “session expired”.
  • Sign out in every tab at once (BroadcastChannel), and after the idle timeout.
  • Double-submit guard, a generic error message for every failure, a short client-side cool-down after 5 failures (UX only — the server must rate-limit), password manager friendly autocomplete attributes.
  • Permissions: can: 'orders.view' on any block or sidebar item; VerxeeUI.can('x') in code.

Calling your API: VerxeeUI.fetch

const r = await VerxeeUI.fetch('/api/orders', { method: 'POST', json: { sku: 'A1' } });

Same-origin cookies, the CSRF header on unsafe methods (token from <meta name="csrf-token"> or an XSRF-TOKEN cookie; header name configurable via configure({ security: { csrf: { header } } })) and the 401 handling above.

Programmatic

const shell = VerxeeUI.app({ … });
shell.logout();             // or VerxeeUI.logout('Reason shown on the sign-in screen')
VerxeeUI.user;              // the signed-in user (or null)
